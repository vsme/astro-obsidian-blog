# 表情与短评论

首页日志和足迹（地图详情、下方时间线）均使用独立的表情按钮和短评论按钮。表情选择、取消、评论加一和删除不调用审核；只有发表评论调用 TypeSafe。文章的 Giscus 配置独立。

## SQL 文件与执行方式

- [initialize.sql](./initialize.sql)：当前完整结构，**仅用于尚未建立本功能的新项目**。已包含 HMAC 限流、每日 100 条成功评论额度、归属、互动及权限收紧，不需要再执行本目录已有迁移。
- [migrations/](./migrations/)：已有项目的增量升级，按文件时间顺序执行尚未应用的文件。
- [legacy/](./legacy/)：历史基础 SQL，内容保留用于追溯和初始化脚本再生成，不作为当前新项目的部署入口。不要在升级后重新执行，以免恢复旧接口或权限。

已有项目必须先具备基础评论、归属和互动结构，再依次应用：

1. [评论发表额度升级](./migrations/20261009235246_diary_comment_rate_limits.sql)：每日 100 条成功发表，审核失败不计日额度。
2. [表情 HMAC 升级](./migrations/20261010015855_emoji_rate_limit_hmac.sql)：清理旧原始 IP 限流记录，关闭旧客户端写入路径。
3. [权限与旧函数清理](./migrations/20261010022122_interaction_schema_cleanup.sql)：限制管理函数、合并评论读取、移除已停用入口。这个升级不删除任何数据，可重复执行。
4. [足迹评论支持](./migrations/20261010050003_footprint_comments.sql)：允许足迹内容 ID，共用日志的评论、归属和互动逻辑，不改已有数据。
5. [作者参与与防误删](./migrations/20261010141752_comment_author_participation.sql)：保存作者参与状态，允许作者取消/恢复自己的那 1 人，并在存在他人互动时禁止删除。

按已经应用的版本执行剩余迁移；已完成足迹评论升级的项目，本次只执行第 5 个，再部署新版函数和前端。若旧项目只有表情、尚未开通短评论，先按 [历史文件说明](./legacy/README.md) 建立评论基础结构，再执行上述升级。

新项目在 SQL Editor 执行 `initialize.sql` 一次。脚本会主动拒绝已经存在本功能表或私有 schema 的项目，避免被误用作线上覆盖脚本。旧项目不要执行初始化脚本。当前说明使用 SQL Editor 工作流；完整初始化不会替你登记 Supabase CLI 的迁移历史。

## 部署函数及前端

继续使用已有 Supabase 项目的前端 `SUPABASE_URL` 和公开的 `SUPABASE_KEY`。以下服务端配置仅放在 Edge Function Secrets：

| 名称                      | 用途                                                                                                                                                                                          |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `COMMENT_ALLOWED_ORIGINS` | 必填，逗号分隔的完整 origin，例如 `https://example.com,https://preview.example.com`；请替换成实际站点地址，包含协议及实际端口，不加路径或末尾 `/`；本地调试地址仅配置在个人环境中，不写入仓库 |
| `TYPESAFE_API_KEY`        | 发表评论必填，TypeSafe 审核密钥；表情、读取和删除不依赖它                                                                                                                                     |
| `TYPESAFE_MODEL`          | 选填，默认 `jev-1.13.0`                                                                                                                                                                       |

Supabase 提供服务端 `SUPABASE_SERVICE_ROLE_KEY` 等内置配置。不能把服务端密钥放入前端或 `PUBLIC_` 环境变量。无需另设 `COMMENT_RATE_SECRET`。配置方法见 [官方 Secrets 文档](https://supabase.com/docs/guides/functions/secrets)。

在项目根目录部署完整函数及其相对依赖，不要只复制单个 `index.ts`：

```sh
npx supabase@latest functions deploy diary-comment --project-ref YOUR_PROJECT_REF --use-api
```

将命令中的 `YOUR_PROJECT_REF` 替换成你自己的项目编号，不将个人配置写入提交文件。

`supabase/config.toml` 为匿名访客关闭网关 JWT 校验，函数自行校验公开 API key、origin 和服务端限流；函数仍使用服务端凭据访问私有数据。部署说明见 [Supabase 官方文档](https://supabase.com/docs/guides/functions/deploy)。

尚未切换到 HMAC 写入的旧项目，应在同一部署窗口完成新版函数、待应用 SQL 和前端发布。HMAC 升级后旧前端的表情写入会被拒绝，直到前端更新；已有数据和读取保留。权限清理升级保持当前 Edge RPC 名称和响应格式，已更新的前端及函数无需为此更换接口。

## 读取、归属与权限

日志和足迹读取用一次批量 `list` 请求同时获取表情与评论；Edge Function 并行调用 `get_content_reactions_many` 和 `get_diary_comments_for_viewer`。进入可见区域附近 200px 时加载，20ms 合并窗口，每批最多 50 个内容 ID。内存及 localStorage 缓存有效期五分钟；评论缓存每个浏览器凭证最多 100 个内容。写入后的旧响应不会覆盖较新的本地状态。

评论读取统一为一个服务端 SQL 查询：每条内容最近 20 条公开评论，再包含自己的最近 20 条，合并去重。历史 pending 只对正确归属凭证的作者返回，便于删除；新提交不再创建 pending。不存在旧后端回退路径。

评论归属使用浏览器保存的 256 位随机凭证，数据库只保存 SHA-256 摘要。作者默认参与，显示人数为他人互动数加上作者当前参与状态。只有作者一人时隐藏角标，首次他人互动显示 `+2`。已有他人互动时，作者点击只取消/恢复自己的参与，不删除评论或他人的互动。作者尚未取消且没有他人互动时，点击才由服务端允许弹出删除确认；历史 pending 仍可由本人确认删除。私有表保存选填邮箱和审核结果，公开接口及缓存不包含这些字段或凭证摘要。

管理、触发器和评论内部函数仅授权 `service_role`，并使用 `SECURITY INVOKER` 和空 `search_path`。表情触发器继续维护统计缓存。仅两条表情公开读取函数保留受控 `SECURITY DEFINER`，供足迹及浏览器读取使用。

清理迁移删除旧未使用的无归属保存、旧布尔限流、旧评论列表/互动状态、旧表情原始 IP 写入和 SQL IP 读取函数。删除不使用 `CASCADE`；如果数据库另有显式依赖，迁移应整体失败并保留原状态，而不是连带删除对象。仍被调用的保存、删除、互动和限流辅助函数继续保留。

## 限流及 IP 隐私

- 评论提交：每个来源每分钟 5 次，全站每分钟 30 次；审核失败和重复尝试计分钟预算，但不计每日发表额度。
- 评论发表：每个来源每天 100 条成功发表。额度加一与保存评论处于同一事务；保存失败回滚额度，删除不退还额度。UTC 零点重置，对应北京时间 08:00。
- 评论加一及取消：每个来源每分钟 30 次、每天 500 次，全站每分钟 120 次。
- 表情选择及取消：每个来源每分钟 60 次，不消耗评论额度。

429 响应包含原因、限额、重试时间及 `Retry-After`，前端显示北京时间。评论发表和加一的冷却分别缓存，刷新页面后仍生效；表情限流独立。

服务端临时读取请求 IP，以 HKDF 从服务端密钥派生 HMAC-SHA256 密钥。表情和评论使用不同用途，摘要不同；数据库只收到摘要。服务端密钥、项目 URL 和用途不变时摘要稳定，密钥轮换会进入新限流桶；不会每天自动换密钥。

HMAC 无法直接解密为 IP，但密钥泄露后可通过候选 IP 摘要进行匹配。此功能是带密钥的假名化，不是完全匿名。清理只针对业务表，不清除平台访问日志、备份或历史 WAL。每次写入顺便清理过期限流记录，无请求时不会按秒自动清理。

## 审核与故障提示

文字评论最多 20 个 Unicode 字素，昵称最多 20 字，昵称和邮箱均可留空；昵称提示为“默认匿名”。送审请求只含正文、昵称及昵称规范化结果，不包含邮箱、IP、浏览器身份或内容 ID。

| 审核项                | clear 概率至少 | confidence 至少 |
| --------------------- | -------------- | --------------- |
| 针对人的辱骂/恶意攻击 | 0.75           | 0.60            |
| 正文政治内容          | 0.80           | 0.75            |
| 政治人物昵称          | 0.80           | 0.75            |

三项均为 clear 且达到门槛才发表。单独的赞叹口语“牛逼”不按针对人的辱骂处理；普通短昵称 `hh` 不凭首字母猜测政治身份。violation、uncertain 或低于门槛直接返回 422，显示原因和对应评分，保留草稿；拒绝的正文和邮箱不保存。API 故障返回 503，不发表。中文和拼音审核仍需结合真实样本验证，不能保证零误判或零漏判。

来源不允许时检查 origin；“审核暂时不可用”时检查 TypeSafe 密钥、模型及 Edge 日志；“评论无法加载”时检查 SQL 升级和函数是否完整部署。

## 验证与初始化再生成

```sh
pnpm run test:diary-comments
pnpm run test:interaction-schema
```

SQL 验证需要 PostgreSQL 的 `initdb`、`pg_ctl`、`psql`、`pg_dump` 在 PATH。测试启动仅 Unix socket 的隔离临时数据库，使用虚构数据；不连接线上项目，结束后删除临时库。验证显式匿名权限、服务端写入、合并前后列表一致、历史数据保留、旧函数移除、重复升级、全新初始化防误用及两条路径的结构一致。

当前 `initialize.sql` 由历史基础文件及全部迁移的最终结构生成，不拼接重复定义，也不导出数据。修改迁移后运行下面的命令再生成，并执行上述结构验证：

```sh
pnpm run supabase:init
```

足迹继续使用 `emoji-reactions-footprint-<记录 ID>` 作为互动位置，已有表情计数保持关联。评论位置校验在浏览器、Edge Function 和数据库约束中同时支持日志与足迹；正文和昵称审核、本人删除权限及限额一致。

## 作者参与状态升级

先执行第 5 个迁移，再部署新版 `diary-comment` 和前端。迁移只新增私有布尔字段和替换相关函数，不删除已有评论或互动；已有作者默认参与。客户端不回退旧接口，评论缓存升级为 v2，归属凭证保持原样。

作者点击由服务端加锁后读取最新状态决定：有他人互动时取消参与；已取消时恢复参与；仅作者参与时返回需要删除确认。互动返回作者参与状态和是否需要删除确认，列表对所有读者返回一致的参与状态。点击和取消均使用原有互动限额，不调用审核。

删除操作同样锁定评论行；如果已有他人互动或作者已取消参与，即使旧页面已经打开删除确认，也拒绝删除。拒绝后前端刷新状态并关闭已失效的确认框。作者取消后他人也全部取消，评论仍保留，作者再次点击可恢复参与。

验证包含作者取消/恢复、刷新缓存恢复状态、保留他人记录、旧删除确认防误删，以及他人请求尚未提交时作者点击/删除的并发情况。
